# Standalone Tasks — User Manual

> **Version 1.0 · June 2026**
> This manual covers the Standalone Tasks module from two perspectives: **Team Member** (your personal task inbox) and **Administrator** (creating and managing tasks across the team). Read the section that applies to you, or both if you hold both roles.

---

## What is a Standalone Task?

A standalone task is a direct, one-off work item assigned to a specific team member. Unlike workflow tasks — which are part of multi-step automated processes — standalone tasks are simple: someone assigns you something, you complete it or dismiss it, and that's it.

Common uses include action items from meetings, follow-ups from reviews, or any piece of work that needs to be tracked and confirmed done.

---

## Quick Reference: Status Lifecycle

```
[ PENDING ]  ◄── task assigned, waiting for action
     │
     ├── Mark Complete ──► [ APPROVED ]  (terminal)
     │
     └── Dismiss ────────► [ REJECTED ]  (terminal — comment required)
```

Once a task reaches **Approved** or **Rejected** it cannot be changed.

## Part 1 — Team Member: My Task Inbox

### Where to find it

Navigate to **Tasks → Standalone** from the main menu. This is your personal inbox: you only see tasks assigned to you that are still pending.

### 1.1 Reading your task list

Each row in the inbox shows:

| Column | What it means |
|---|---|
| **Title** | What you need to do |
| **Priority** | `Low`, `Medium`, `High`, or `Critical` |
| **Due Date** | When it should be done — shown in red if overdue |

Tasks are sorted with the earliest due date at the top. If a task has no due date it appears below dated tasks.

### 1.2 Filtering

Use the **Priority** filter at the top of the table to narrow the list. Click **Reset** to clear filters.

### 1.3 Opening a task

Click anywhere on a task row to open the detail drawer. The drawer shows the full title, description, priority, due date, and any comments left by the creator or previous reviewers.

### 1.4 Adding a comment

Before or after resolving a task you can leave a comment in the drawer. Type your message and click **Add Comment**. Comments are permanent — they cannot be edited or deleted once saved. All comments are visible to the administrator who assigned the task.

### 1.5 Marking a task complete

Click **Mark Complete** to confirm that you have finished the work. A comment is optional — you can explain what you did, but it is not required.

For **recurring tasks** (tasks generated from a repeating template), you will also see a file upload field for a meeting transcript. If your task requires uploading one:

1. Attach the transcript file in the upload field
2. Click **Mark Complete**

The system reads the transcript to extract the meeting date, then automatically creates the next instance of the task due in the configured number of days. If you mark the task complete without uploading a transcript, the task closes but the next instance is **not** automatically scheduled — you will see a warning message letting you know.

### 1.6 Dismissing a task

Click **Dismiss** if the task is no longer applicable — for example, it was resolved another way, or it was assigned to you in error.

Dismissing **requires a comment**. Explain briefly why the task is being dismissed. The administrator who created the task will be able to see this comment.

## Part 2 — Administrator: Managing Standalone Tasks

### Where to find it

Navigate to **Tasks → Admin → Standalone Tasks**. This view shows all tasks across the organization — not just your own.

### 2.1 The admin task list

By default the list shows only **pending** tasks. Each row shows:

| Column | What it means |
|---|---|
| **Title** | Task description |
| **Assignee** | Team member the task is assigned to |
| **Priority** | `Low`, `Medium`, `High`, or `Critical` |
| **Status** | `Pending`, `Approved`, or `Rejected` |
| **Due Date** | Shown in red if overdue |
| **Source** | `Internal` (created via the web) or `API` (created by an external integration) |
| **Template** | Populated if the task was generated by a recurring template |

Tasks are sorted by due date ascending (earliest first), then by creation date descending.

### 2.2 Filtering the admin list

Use the filter bar above the table to narrow results:

| Filter | Options |
|---|---|
| **Status** | Pending · Approved · Rejected |
| **Priority** | Low · Medium · High · Critical |
| **Assignee** | Any team member appearing in the list |
| **Source** | Internal · API |
| **Show resolved** | Toggle to include Approved and Rejected tasks |

Click **Reset** to clear all active filters.

### 2.3 Creating a task

Click **Create Task** (top right of the admin list). Fill in the form:

**Title** *(required)*
A short, clear description of what needs to be done.

**Assignee** *(required)*
Search for and select the team member who should complete this task. You can assign a task to any active team member.

**Priority** *(required)*
Select the urgency level:

| Priority | When to use |
|---|---|
| Low | Nice to have; no immediate deadline |
| Medium | Standard follow-up; complete within normal timeframe |
| High | Important; should be addressed soon |
| Critical | Blocking or time-sensitive; needs immediate attention |

**Due Date** *(optional)*
Set a deadline if there is one. Tasks past their due date are automatically flagged as overdue (red date).

**Description** *(optional)*
Add any context, instructions, or links the assignee will need to complete the task.

Click **Save** to create the task. The assignee will see it in their personal inbox immediately.

### 2.4 Cancelling a task

You can cancel any task that is still **Pending**. Click the cancel button on the task row. The system automatically marks it as Dismissed with the comment *"Cancelled by administrator"*.

Approved or rejected tasks cannot be cancelled — they are already terminal.

### 2.5 Viewing task details and comments

Click any row in the admin list to open the same detail drawer that assignees see. From here you can:

- Read the full task details and description
- View all comments in chronological order
- Add your own comment

## Permissions Reference

| Permission | Who holds it | What it unlocks |
|---|---|---|
| `StandaloneTask` read | Assigned team members | View tasks assigned to them |
| `StandaloneTask` create | Assigned team members | Mark Complete, Dismiss, add comments |
| `StandaloneTaskAdmin` read | Administrators | View all tasks across the organization |
| `StandaloneTaskAdmin` create | Administrators | Create tasks, cancel pending tasks |

## Standalone Tasks vs. Workflow Tasks

If you are unsure which type of task you are looking at, here is the quick distinction:

| | Standalone Task | Workflow Task |
|---|---|---|
| **Created by** | An administrator directly | A workflow process template |
| **Steps** | One: complete or dismiss | Multiple, with defined sequence |
| **Assignment** | Always a single person | Routed based on workflow rules |
| **Dependencies** | None | Can be blocked by prior steps |
| **Recurrence** | Optional | Not built-in |

Workflow tasks appear in the **Workflow** tab of the Tasks Hub. Standalone tasks appear in the **Standalone** tab.
